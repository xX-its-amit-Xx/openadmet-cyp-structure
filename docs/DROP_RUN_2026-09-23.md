
The two measured anchors are spread 0.51 -> gain +0.0381 (CYP3A4 Boltz) and 0.83 ->
+0.1448 (P450 protenix). **0.34 sits below both**, i.e. off the calibrated interval, and
the tool says so itself. Two points define a line and nothing more — read it as an order of
magnitude, not a prediction. Directionally it means the pool already agrees with the
reference engines more than the validation pool did, which is consistent with FINDING 012:
the gain is a **catastrophe rate**, and it falls as pools improve. A smaller gain here is
the mechanism working, not a regression.

No bimodality rule was built or applied. `minority_report.py` is hardwired to val87b and
was not run. **No drop-day proxy for the "multiple mutually exclusive conformations"
regime is claimed** (playbook §7).

## 9. Differences from the blind rehearsal, in full

1. **`preflight_parse.py` could not be used** — it dry-parses on Modal, which is over cap.
   Replaced by an equivalent local CPU parse plus Boltz's own in-job schema parser (§1).
   The rehearsal never exercised this step at all (it reuses an existing pool).
2. **Generation was real**, which the rehearsal explicitly does not test. Two Slurm jobs
   instead of one, because `submit` folds one YAML directory per job and the playbook asks
   for ~18-ligand jobs; round-robin packing across the two.
3. **Neither job landed on `gyorilab`.** One V100, one A100; 8.64 and 3.44 min/ligand
   against the documented 8.8 (V100) and 1.6 (H200) budgets. Nothing about the conditioning
   differs — `--no_kernels`, same checkpoint, same MSA, `build_yaml` sha1 unchanged.
4. **Reference depth 8 on 20 of 20 with 0 job failures.** FINDING 038 measured a 6.25%
   per-job failure rate on one observation; the pooled rate is now **1 of 128** (1/16, then
   0/80, now 0/32). The recovery path (`collect`, then re-run the identical `submit`) was
   therefore never exercised today.
5. **`dropped_same_wave` is 0 where FINDING 038 reported 272** — purely because `--samples`
   now defaults to 1. Verified by the 0.168 Å minimum pairwise Chamfer instead.
6. **The composition is the real difference: 45% non-coordinating against 16%.** Every
   expected-score number in the repo was measured on a 16%-Type-I population.
7. **The pool's within-ligand xeng spread (0.34) is below both calibration anchors**, so
   the expected cross-engine gain is extrapolated, not interpolated. Flagged as such.
8. Minor: the local preflight reports the *upper* median heavy-atom count (24); the drop
   commit message quotes 23. Both are the same sorted array.

### Residual risk, named rather than fixed

The PDBs carry Boltz's own protein numbering, **1..503**, as every prior submission from
this repo has (`build_submission.py` does no renumbering, by design — on a blind set there
is no reference to renumber *to*). FINDING 021 / T1 is a scoring-side hazard and our own
scorer handles it; whether the portal's does is not something this repo can verify, and the
PXR entry scored 0.564 built exactly this way. **Any returned score of exactly 0.0000 is
this bug until proven otherwise.**
